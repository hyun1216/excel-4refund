## 1. 결론

운영 폴더는 기존 위하고 경정청구 구조를 유지하고, `1. 급상여현황 생성` 아래에 원본 전용 `1.Input` 폴더만 추가하는 구성이 적합하다.

- 원본 급여대장과 원천징수영수증은 새 `1.Input`에만 적재한다.
- `회사명_기초정보.xlsx`는 차수별 파일을 만들지 않고 업체 폴더의 단일 마스터 파일로 계속 갱신한다.
- 생성된 연도별 급여대장은 기존 위하고와 동일하게 `2.근로소득 수정신고\1.Input`에 저장한다.
- 분할한 개인별 원천징수 PDF가 필요하면 기존 `원천징수(PDF)` 폴더를 사용한다.
- `temp`와 `temp\output\trans`는 개발·검증용 경로로만 사용하고 운영 경로로 사용하지 않는다.

### 2.2 원천징수영수증에서 기초정보를 만드는 파일

| 처리 순서 | 파일·함수 | 역할 |
|---:|---|---|
| 1 | `payroll_converter.py`의 `PayrollConverter._document_signature()` | PDF가 원천징수영수증인지, 소득자별 원천징수부인지, 표형 급여대장인지 판별 |
| 2 | `payroll_converter.py`의 `_receipt_year()` | 파일명과 PDF 본문에서 귀속연도 판정 |
| 3 | `payroll_converter.py`의 `_split_bundle()` | 전체 사원 통합 원천징수영수증을 개인별 PDF로 임시 분할 |
| 4 | `withholding_pdf_excel.py` | 개인별 PDF의 인적사항, 소득, 비과세, 세액 및 공제 값을 구조화 |
| 5 | `withholding_basic_info.py`의 `_extract_all()` | 개인별 추출을 연도 단위로 묶고 오류를 전파 |
| 6 | `dawon_pipeline.py`의 `build_dawon_basic_info()` | 공용 템플릿에 회사정보와 연도별 `원천징수추출(YY년)` 시트를 작성 |
| 7 | `payroll_converter.py`의 `_update_basic_info_item_headers()` | 급여대장에서 확인한 전체·연도별 지급/공제 항목을 `사업장정보` 시트에 적재 |
| 8 | `employee_info.py`의 `populate_basic_info_employee_sheets()` | 고용정보현황조회를 `직업분류코드` 시트에 매핑하고 사업장가입자명부를 `건보정보` 시트에 적재 |

`build_dawon_basic_info()`라는 이름은 최초 다원 샘플에서 시작된 흔적이다. 현재는 회사명을 고정하거나 다원 전용 좌표를 사용하는 실행기가 아니며, 추출된 회사정보와 연도별 원천징수 자료를 받아 공용 기초정보 템플릿을 작성한다.

### 2.3 급여대장을 만드는 파일

| 처리 순서 | 파일·함수 | 역할 |
|---:|---|---|
| 1 | `dawon_pipeline.py`의 `_parse_payroll_name()` | `YYYYMM_n.pdf`, `YY년 M월 ... 급여대장.pdf` 형식에서 연·월·분할번호 판정 |
| 2 | `dawon_pipeline.py`의 `_main_payroll_table()` | 페이지에 표가 여러 개 있어도 헤더 시그니처로 급여 본문 표 선택 |
| 3 | `dawon_pipeline.py`의 `parse_dawon_payroll_pdf()` | 다단 세로형 및 다행 격자형 PDF를 직원 1명당 1행으로 정규화 |
| 4 | `dawon_pipeline.py`의 `build_dawon_payroll_workbook()` | 같은 연도의 PDF를 월별로 묶고 12개 월 시트가 있는 중간 급여대장 생성 |
| 5 | `payroll_converter.py`의 `normalize_and_map_columns()` | 헤더 정규화와 동의어 매핑, 미분류 지급·공제 항목 처리 |
| 6 | `payroll_converter.py`의 `validate_totals()` | 지급항목 합계, 공제항목 합계, 차인지급액 검증 |
| 7 | `payroll_converter.py`의 `convert_excel_workbook()` | 월별 표준 급여대장을 최종 `회사명_YY년 급여대장.xlsx`로 저장 |

모든 급여 PDF는 다음 세 검증을 통과해야 최종 파일로 이동한다.

1. 직원별 지급항목 합계와 지급합계가 일치해야 한다.
2. 직원별 공제항목 합계와 공제합계가 일치해야 한다.
3. 지급합계에서 공제합계를 뺀 값과 차인지급액이 일치해야 한다.

### 4.1 원본 투입 위치

| 원본 종류 | 투입 위치 | 비고 |
|---|---|---|
| 월별 또는 연도별 급여대장 PDF | `Income_Tax_Path\1.Input\급여대장\` | 모든 연도의 원본을 한 폴더에 적재하며 파일명과 PDF 내용으로 연·월을 판정 |

원본 폴더에는 업체가 제공한 파일만 넣는다. 연도별 하위 폴더를 만들 필요는 없으며 여러 연도의 파일이 섞여 있어도 변환기가 파일명과 PDF 본문에서 연도를 판정한다. 생성된 Excel, 검증보고서, 개인별 분할 PDF를 원본 폴더로 되돌려 넣지 않는다.

| 결과 | 출력 위치 | 파일명 |
|---|---|---|
| 기초정보 마스터 | `Company_Path` | `{업체명}_기초정보.xlsx` |

## 5. Config.xlsx에 추가할 입력 경로

기존 출력 경로 키를 재사용할 수 있으므로 새 출력 키는 필요하지 않다. 빈 행에 원본 입력 경로 키만 추가하면 된다.

| 권장 키 | 권장 수식 | 용도 |
|---|---|---|
| `Source_Input_Path` | `=$C$10&TEXT("1.Input\",)` | 업체 원본 입력 기준 폴더 |
| `Payroll_Source_Path` | `=$C$25&TEXT("급여대장\",)` | 원본 급여대장 투입 폴더 |
| `Withholding_Source_Path` | `=$C$25&TEXT("원천징수영수증\",)` | 원본 원천징수영수증 투입 폴더 |
| `Withholding_Ledger_Source_Path` | `=$C$25&TEXT("소득자별근로소득원천징수부\",)` | 원본 소득자별 원천징수부 투입 폴더 |

위 표는 현재 Config의 마지막 사용 행 다음인 25~28행에 순서대로 추가하는 것을 전제로 한다. 행을 변경하면 `$C$25` 참조도 실제 `Source_Input_Path` 셀에 맞춰 조정해야 한다.

## 6. 운영 실행 순서

1. Config에서 `Company_Path`, 신규 원본 입력 경로, 기존 출력 경로를 계산한다.
2. 업체 폴더와 `1. 급상여현황 생성\1.Input` 하위 폴더가 없으면 생성한다.
3. 사용자는 원본 급여대장과 원천징수영수증만 각 입력 폴더에 적재한다.
4. 실행기는 원본을 수정하지 않고 파일 목록과 SHA-256을 기록한다.
5. 원천징수영수증을 개인별로 분할하고 기초정보 데이터를 추출한다.
6. 급여대장을 헤더명으로 분석하고 월별 직원 1행 형태로 정규화한다.
7. 직원별·월별·원본 전체 합계를 검증한다.
8. `{업체명}_기초정보.xlsx`와 연도별 급여대장을 임시 폴더에서 완성한다.
9. 모든 검증이 통과하면 지정된 운영 출력 위치로 한 번에 이동한다.
10. 오류가 발생하면 기존 결과를 덮어쓰지 않고 검증보고서에 파일명, 페이지, 직원명 및 불일치 항목을 기록한다.

## 7. 운영 적용 전에 필요한 최소 개발

현재 변환 코어는 기초정보와 급여대장을 생성할 수 있지만 Config 기반 운영 실행은 아직 연결되지 않았다. 다음 변경만 추가하면 된다.

1. `Resources\Config.xlsx`에서 경로 키와 `BasicInfo_FileName`을 읽는 로더를 추가한다.
2. 업체명을 받아 권장 폴더를 생성하는 초기화 함수를 추가한다.
3. `PayrollConverter.convert_all()`이 업체별 `1.Input` 자체를 직접 처리할 수 있게 공개 단일업체 메서드를 제공한다. 운영 코드에서 현재의 private `_convert_tabular_group()`을 직접 호출하지 않는다.
4. 기초정보, 연도별 급여대장, 검증보고서를 각각 본 보고서의 운영 위치로 라우팅한다.
5. `run_app.bat`와 분리된 기초정보·급여대장 전용 실행 파일을 추가하거나 기존 CLI에 별도 명령을 등록한다.

## 8. 현재 테스트 경로와 운영 경로 구분

`D:\RPA\Python_4refund\temp\모빌인 경정청구`와 `temp\다원로지스틱스 경정청구`는 개발 샘플이다. `temp\output\trans`도 테스트 결과 확인용이다. 정식 실행에서는 이 경로를 참조하지 않고 Config가 계산한 업체별 `1.Input`과 운영 출력 경로만 사용해야 한다.

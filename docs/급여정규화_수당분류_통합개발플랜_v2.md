# 환급대상 추출·근로소득 수정신고 통합 개발 플랜 v2

> 작성일: 2026-10-14  
> 기준 문서: `Python_환급대상_근로소득_통합개발플랜.md`  
> 추가 기준 구현: `payroll_pdf_converter`, `4refund_wehago`  
> 범위: 파일 입력부터 수정신고 제출 ZIP 생성까지. Google Drive 업로드와 이메일 발송은 제외한다.

## 1. 이번 플랜의 핵심 변경

기존 플랜의 큰 구조는 유지하되 다음 두 단계를 선행 필수 단계로 확정한다.

1. 모든 급여자료는 `payroll_pdf_converter`의 검증된 방식으로 먼저 정규화한다.
2. 정규화 결과만 `4refund_wehago`의 지급항목 분류와 급상여현황 생성 로직에 전달한다.

따라서 최종 처리 순서는 다음과 같다.

```text
원본 등록
  → 급여 원본 유형·월·분할파일 식별
  → 급여대장 정규화
  → PDF 원본합계와 정규화합계 대사
  → 지급항목 카탈로그 생성
  → 정액급여·수당검토·제외 분류
  → 직원/원천징수/직업분류 결합
  → 대상자·대상월 판정
  → 급상여현황 생성
  → 사람 검토·승인
  → 조정 급여대장 및 수정 원천징수 생성
  → 추가서류·제출 임금대장 생성
  → 전체 대사 및 제출 ZIP 생성
```

정규화에 실패했거나 지급총액·공제총액·실지급액이 원본과 맞지 않으면 수당 분류 이후 단계로 진행하지 않는다.

## 2. 구현 원칙

- 원본 PDF·Excel·ZIP은 읽기 전용으로 보존하고 SHA-256을 기록한다.
- 계산의 기준 데이터는 파일명이 아니라 구조화된 표준 급여 원장이다.
- 직원 식별은 사원번호를 기본 키로 사용하고, 주민등록번호와 성명으로 교차검증한다.
- 주민등록번호·성명·사원번호가 모순되거나 중복되면 자동 병합하지 않는다.
- 지급항목의 과세·비과세 성격을 이름만 보고 새로 추정하지 않는다.
- 기존 O01 비과세 연장근로 항목은 재조정 대상으로 사용하지 않고 보호한다.
- 자동 분류 결과와 사람의 승인 결과를 구분해 저장한다.
- 법정 기준금액은 코드에 흩어놓지 않고 연도별 규칙 테이블로 관리한다.
- 단계별 결과를 저장하여 실패한 단계부터 재실행할 수 있게 한다.
- Google Drive·메일 전송은 실행 그래프에서 제거한다.

## 4. S02 급여자료 인벤토리와 그룹화

### 4.1 입력 지원

- 급여대장 PDF
- 이미 정리된 Excel 급여대장
- 월별 PDF가 여러 파일로 분할된 자료
- ZIP 내부의 연도·월별 급여자료

입력 유형마다 파서는 달라도 S03 출력 계약은 같아야 한다.

### 4.2 분할 PDF 그룹 규칙

`payroll_pdf_converter`의 월별 그룹화 규칙을 재사용한다.

- `yyyyMM_1.pdf`, `yyyyMM_2.pdf`, …, `yyyyMM_n.pdf`를 같은 월로 묶는다.
- `_1`, `_2`로 고정하지 않고 임의의 양의 정수 접미사를 지원한다.
- 정렬은 문자열 순서가 아니라 접미사 숫자 순서로 한다.
- 하위 폴더를 재귀 탐색할 때는 서로 다른 부모 폴더의 동명 파일을 합치지 않는다.
- 규칙에 맞지 않는 파일은 독립 자료로 보존하고 자동 병합하지 않는다.
- 같은 월에 분할 번호가 중복되면 실패 처리한다.
- 분할 번호가 건너뛰는 경우 경고를 남기되, 원본 합계 대사가 가능할 때만 검토 대상으로 둔다.

### 4.3 인벤토리 산출물

## 5. S03 급여대장 정규화

### 5.1 PDF 표 구조 판독

`payroll_pdf_converter`의 다음 동작을 서비스로 이식한다.

1. 각 페이지 첫 번째 급여 표를 찾는다.
2. 표 상단 헤더를 최대 3개 물리행으로 읽는다.
3. PDF 셀 경계 때문에 잘린 헤더를 복구한다.
4. `소득금액`과 `공제금액` 그룹 헤더의 실제 열 경계로 지급·공제 열을 분류한다.
5. `지급총액`, `공제총액`, `실지급액`은 항목 열과 분리해 합계 열로 고정한다.
6. 같은 항목명이 지급과 공제 양쪽에 나타나면 자동 처리하지 않고 실패한다.
7. 직원 블록의 텍스트를 물리 좌표로 다시 묶어 직원 1명당 1행으로 만든다.
8. 직원 블록 마지막의 근무시간 정보 행은 급여 금액으로 읽지 않는다.
9. 거래처명은 합계행을 우선 사용하고, 없으면 페이지 헤더를 보조값으로 사용한다.
10. 원본 파일과 페이지 번호를 모든 직원 행에 남긴다.

새로운 PDF 서식은 기존 프로필로 억지 해석하지 않는다. 헤더 시그니처가 다르면 별도 파서 프로필을 추가하고 기존 프로필 회귀검사를 수행한다.

### 5.2 값 정규화

- 날짜는 정렬 가능한 표준 날짜로 변환한다.
- 금액은 쉼표, 공백, 음수표기 등을 정리해 숫자로 저장한다.
- 사원번호와 주민등록번호는 앞자리 0이 사라지지 않는 문자열로 저장한다.
- 공란과 실제 0원을 구분한다.
- 헤더의 괄호, 줄바꿈, 불필요한 공백은 비교키에서만 제거하고 원본 표시명은 별도로 보존한다.
- 지급항목과 공제항목의 원본 등장 순서를 각각 유지한다.

### 5.3 표준 급여 원장 계약

정규화 결과는 넓은 Excel 한 행을 바로 업무 기준으로 쓰지 않고 아래 long-form 원장을 기본으로 저장한다.

### 5.4 월별 병합

- 각 `_n` PDF를 먼저 독립적으로 파싱한다.
- 직원행에는 실제 원본 파일명을 남긴다.
- 지급·공제 항목 목록은 최초 등장 순서를 유지하며 중복 제거한다.
- PDF별 전체합계를 모두 읽었을 때만 월 전체 원본합계를 합산한다.
- 일부 파일에서 전체합계를 읽지 못하면 해당 월을 `NEEDS_REVIEW`로 둔다.

### 5.5 G0 정규화 검증 게이트

다음 항목을 월별로 검증한다.

- 지급총액: 직원행 합계 = PDF 전체합계
- 공제총액: 직원행 합계 = PDF 전체합계
- 실지급액: 직원행 합계 = PDF 전체합계
- 직원행별 `지급총액 - 공제총액 = 실지급액`
- 사원번호 중복 및 공란
- 동일 직원·동일 월·동일 급여구분 중복
- 지급/공제 양쪽에 동일 항목명 존재 여부
- 표 미인식 페이지와 거래처 미확정 직원 존재 여부

판정은 다음과 같다.

- `PASS`: 원본합계 3종이 모두 일치하고 필수 식별값 오류가 없음
- `NEEDS_REVIEW`: 원본합계 자체가 인식되지 않았거나 비치명 경고가 있음
- `FAILED`: 합계 불일치, 중복키, 지급·공제 충돌, 필수 열 누락

`PASS`가 아닌 월은 S04 수당 분류에 포함하지 않는다. 사용자가 승인한 예외만 별도 승인 기록과 함께 재개할 수 있다.

## 6. S04 지급항목 카탈로그

정규화 원장의 지급항목만 모아 연도별 카탈로그를 만든다. 공제항목은 수당 분류 대상에서 제외하되 제출 급여대장에는 보존한다.

### 6.1 항목 비교키

`4refund_wehago`의 `normalize_item_name` 규칙을 사용한다.

- 대소문자 차이 제거
- 괄호 `() [] {} <>`와 전각 괄호 및 내부 내용 제거
- 공백·하이픈·특수문자 제거
- 글자와 숫자만 남겨 비교키 생성

원본 항목명과 표준 항목명은 삭제하지 않고 매핑 테이블에 함께 저장한다.

### 6.2 중복·충돌 정책

- 같은 비교키에 서로 다른 직접 매핑이 있으면 실패한다.
- 한 원본 항목이 정액급여와 수당검토 키워드에 동시에 걸리면 실패한다.
- 지급항목이 공제항목과 같은 이름으로 발견되면 S03에서 이미 차단한다.
- 신규 미분류 항목은 자동으로 수당검토에 넣지 않고 `UNCLASSIFIED`로 둔다.

## 7. S05 수당 분류

수동 모드와 자동 모드를 모두 지원하되 운영 기본은 자동 초안 + 사람 승인으로 한다.

### 7.1 자동 분류 우선순위

`4refund_wehago`와 동일한 순서를 고정한다.

1. 기존 O01 비과세 연장근로 항목 보호
2. 직접 매핑
3. 제외규칙
4. 키워드 규칙
5. 미분류

직접 매핑이 제외 키워드보다 우선하므로 예를 들어 `차량유지비`는 직접 매핑으로 정액급여가 될 수 있지만, 그 밖의 차량 관련 항목은 제외규칙을 따른다.

### 7.2 분류값

- `FIXED_SALARY`: 정액급여
- `REVIEW_ALLOWANCE`: 수당검토
- `EXCLUDED`: 자동 조정 제외
- `PROTECTED_NON_TAX`: 기존 O01 비과세 항목
- `UNCLASSIFIED`: 규칙 미일치, 사람 확인 필요

### 7.3 기본 분류 정책

정액급여 후보에는 기본급·본봉·기준급·월급·식대·식사대·직무·직책·직급·근속·자격·면허·기술·보육수당 등의 직접 매핑과 확정 키워드를 사용한다.

수당검토 후보에는 연장·시간외·초과근로·잔업·야간·심야·휴일·주말근로·특근·대근 계열을 사용한다.

다음 성격은 자동 조정에서 제외한다.

- 기존 비과세 연장근로수당
- 고정OT·정액OT·고정연장·포괄임금
- 보전·조정
- 상여·성과·인센티브·실적
- 소급·정산
- 퇴직·연차
- 출장·여비·실비
- 경조·학자금
- 직접 매핑되지 않은 차량·자가운전·교통 항목

규칙은 사용자가 편집 가능한 `지급항목_매칭표.xlsx` 또는 동일 구조의 데이터 테이블로 관리한다.

## 8. S06 직원·원천징수·직업분류 결합

- 당해연도 원천징수는 전체 주민등록번호 + 정규화 성명으로 매칭한다.
- 전년도 원천징수는 같은 키로 합산하며, 당해연도에는 존재하지만 전년도에 없으면 신규사원으로 보고 전년도 과세소득을 0원으로 둔다.
- 직업분류는 기존 로직과 동일하게 주민등록번호 앞 7자리 + 정규화 성명으로 매칭한다.
- 당해 원천징수 중복, 주민번호/성명 오류, 필수 데이터 미매칭 직원은 강제 비대상 처리한다.
- 강제 비대상 사유는 결과 파일과 오류목록에 기록한다.

## 9. S07 대상자·대상월 판정

연도별 기준은 규칙 테이블로 관리한다. 현재 `4refund_wehago`에서 확인된 기준은 다음과 같다.

| 적용연도 | 월 정액급여 한도 | 전년도 과세소득 한도 | 연간 기존 비과세 연장근로 한도 |
|---|---:|---:|---:|
| 2021~2025 | 2,100,000원 | 30,000,000원 | 2,400,000원 |
| 2026 이후 | 2,600,000원 | 37,000,000원 | 2,400,000원 |

대상월은 다음 조건을 모두 만족해야 한다.

```text
월 정액급여 합계 <= 해당 연도 월 한도
AND 전년도 과세소득 <= 해당 연도 한도
AND 직원이 강제 비대상 목록에 없음
```

직원별 기존 O01 비과세 연장근로 연간합계가 연 한도를 초과하면 조정 대상에서 제외하고 사유를 기록한다.

법령 또는 운영기준이 바뀌면 기존 구간의 종료연도를 닫고 새 구간을 추가한다. 새 연도 기준이 등록되지 않았으면 실행을 중단한다.

## 10. S08 급상여현황 생성

`4refund_wehago`의 출력 계약을 유지한다.

### 10.1 필수 시트

- `전체인원`: 정규화된 전체 직원·월 자료와 합계행
- `대상자(작업)`: 대상월만 포함하며 조정용 열을 추가
- `비대상자`: 대상자로 선정되지 않은 직원 자료

### 10.2 열 구성

- 기본 식별열: 사원번호, 성명, 주민등록번호, 지급년월, 급여구분
- 지급항목: 원본 지급 순서 유지
- 조정열: `야간연장수당(비과세)`를 지급합계 바로 앞에 배치
- 합계열: 지급합계, 공제합계, 차인지급액
- 판정 보조열: 직업분류, 전년도 과세소득, 강제 비대상 사유

### 10.3 대상자 작업행

- 정액급여 항목, 수당검토 항목, 기존 O01 항목을 구분한다.
- 기존 O01 항목을 수당검토 열로 중복 선택할 수 없게 한다.
- 같은 직원·같은 지급월 행의 중복을 허용하지 않는다.
- 자동 판정 제외항목과 제외 이유를 별도 로그로 남긴다.
- 대상자 조정액은 시스템이 임의 확정하지 않고 검토 가능한 초안으로 제공한다.

### 10.4 합계행과 검증

- 직원별 월별행 뒤에 합계행을 생성한다.
- 정규화 원장의 직원별·항목별 합계와 급상여현황 합계행이 같아야 한다.
- 원천징수 당해연도 금액과 전년도 과세소득을 합계행에 연결한다.
- 주민번호 중복, 원천징수 중복, 직업분류 미매칭을 시각적으로 표시하고 오류목록에도 기록한다.

## 11. G1 수당 검토·승인

승인 파일 또는 승인 레코드는 다음 정보를 반드시 가진다.

```text
company_id, year, employee_code, payroll_month,
source_item_name, approved_non_tax_amount,
reason, reviewer, approved_at, source_version
```

- 승인값은 정규화 원본을 덮어쓰지 않고 조정 원장에 별도 저장한다.
- 원본 해시나 급상여현황 버전이 바뀌면 기존 승인은 무효 처리한다.
- 미분류 항목, 금액 공란, 원본보다 큰 조정액은 승인 불가로 처리한다.
- 승인 전에는 수정 원천징수와 제출 패키지를 생성하지 않는다.

## 12. S09~S12 수정신고 산출물

### S09 승인 조정값 반영

- 승인된 대상월·수당만 과세 지급액에서 차감하고 비과세 항목에 가산한다.
- 지급총액 및 차인지급액 보존 여부를 직원·월별로 검증한다.
- 조정 전·후 항목별 차이를 변경 원장으로 저장한다.

### S10 급여대장 생성

`4refund_wehago`의 급여대장 생성 계약을 적용한다.

- `전체인원`을 기준으로 월별 행 순서를 유지한다.
- 동일 사원번호·지급월의 `대상자(작업)` 행이 있으면 해당 행으로 교체한다.
- 대상자 행이 전체인원에 존재하지 않으면 실패한다.
- `차인지급액`까지의 열을 제출 급여대장에 포함한다.
- 연간 파일은 `01월`~`12월` 시트를 생성한다.
- 필요 시 급여/상여 구분별 파일 출력은 호환 옵션으로 제공한다.

### S11 수정 원천징수

- 기초정보, Tool Data, 원본 PDF를 PDF 인덱스로 연결한다.
- 주민등록번호를 반드시 교차검증한다.
- 3페이지·4페이지 양식을 모두 보존하고 공통 수정영역만 변경한다.
- 저장 후 페이지 수와 PDF 재열기를 검증한다.
- 직원별 수정 금액과 결과 파일을 대사 CSV로 남긴다.

### S12 추가서류·제출 임금대장

- 개인정보 없는 승인 템플릿만 사용한다.
- 템플릿 버전과 해시를 기록한다.
- 경정 명단, 지방세 관련 명단, 생산직 근로자 명단, 사유서, 기관 제출 임금대장을 템플릿별 Writer로 분리한다.
- 양식이나 셀 매핑이 미승인 상태면 `NEEDS_REVIEW`로 중단한다.

## 13. S13 전체 검증

### 13.1 데이터 대사

- 원본 PDF 합계 = 정규화 원장 합계
- 정규화 원장 합계 = 급상여현황 전체인원 합계
- 전체인원 = 대상자 + 비대상자
- 조정 전 지급총액 = 조정 후 지급총액
- 승인 조정액 합계 = 과세 차감 합계 = 비과세 가산 합계
- 급상여현황 합계 = 월별 급여대장 합계
- 수정 원천징수 대상자 수 = 승인 대상자 수

### 13.2 구조 검증

- 필수 시트와 헤더 순서
- 사원번호·지급월 유일성
- 주민번호·성명·PDF 인덱스 일치
- 수식 오류와 깨진 참조
- PDF 원본·결과 페이지 수
- ZIP 무결성 및 파일 해시

### 13.3 시각 검증

- 새 급여 PDF 프로필은 대표 페이지를 렌더링해 열 경계와 행 결합을 확인한다.
- 생성 급상여현황과 제출 임금대장은 모든 시트를 렌더링하거나 Excel에서 표본 검토한다.
- 수정 원천징수는 3페이지형과 4페이지형을 각각 표본 검토한다.

## 14. 상태와 재실행

단계 상태는 SQLite에 저장한다.

```text

NEEDS_REVIEW
```

- 회사 또는 연도 하나가 실패해도 `allow_partial` 모드에서는 다른 연도를 계속 처리한다.

## 18. 인수 기준

다음을 모두 충족해야 완료로 판정한다.

1. `payroll_pdf_converter`의 기존 검증 샘플과 분할 월 자료가 동일 합계로 정규화된다.
2. 새 서식은 헤더 시그니처 기반으로만 별도 파서를 활성화하고 일반 서식 회귀검사가 통과한다.
3. 정규화 PASS 자료만 수당 분류와 급상여현황 생성에 사용된다.
4. `4refund_wehago`의 지급항목 분류 우선순위와 연도별 대상자 판정 결과가 Golden 샘플에서 일치한다.
5. 전체인원·대상자·비대상자와 월별 급여대장 합계가 표준 원장과 일치한다.
6. 승인되지 않은 수당 또는 금액은 수정신고에 반영되지 않는다.
7. 수정 원천징수 대상자·주민번호·PDF 인덱스·금액이 모두 대사된다.
8. 추가서류와 제출 임금대장은 승인 템플릿으로 생성되고 시각검증을 통과한다.
9. 실패 또는 검토 필요 단계가 있으면 최종 제출 ZIP이 생성되지 않는다.
10. Google Drive 업로드와 이메일 발송 없이 로컬 결과 ZIP까지 생성된다.

## 19. 현재 구현본에 대한 적용 순서

현재 `4refund_excel/payroll_amendment`에는 입력검증, 단순 급여대장 생성, PDF 렌더링, 수정 원천징수, 상태 DB 및 패키징 골격이 있다. 다음 순서로 교체·확장한다.

1. 기존 `payroll.py`가 수정 급상여현황을 바로 월별 분리하기 전에 S02~S03 정규화 계층을 추가한다.
2. 현재의 단순 행 결합을 표준 급여 원장 기반 피벗으로 바꾼다.
3. `payroll_pdf_converter`의 그룹화·헤더·지급공제 분류·합계검증을 `normalization/`으로 이식한다.
4. `4refund_wehago`의 지급항목 규칙과 대상자 판정을 `payroll/`으로 이식한다.
5. 급상여현황 3개 시트와 오류목록·교정계획을 생성한다.
6. 승인 게이트 뒤에 현재 월별 급여대장 및 수정 원천징수 단계를 연결한다.
7. 빈 추가서류 템플릿 확보 후 S12 Writer와 S14 최종 ZIP을 활성화한다.

이 순서를 지키면 현재 구현된 수정 원천징수 기능을 버리지 않고, 앞단의 급여 정규화와 수당 분류를 검증 가능한 방식으로 보강할 수 있다.
